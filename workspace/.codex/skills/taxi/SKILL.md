# taxi

只有一条路线：家 → 公司，地址和车型在 `~/.mihome/didi.json`（样例 `didi.example.json`），脚本输出里的 `route`、`product` 就是这条路线和车型。别的目的地就说「现在只能叫去公司的车」。

所有操作只通过这个脚本（工作区相对路径），不要直接调滴滴或其他打车接口：

```
python3 .codex/skills/taxi/taxi.py estimate | order | status | cancel
```

脚本输出一行 JSON。`env` 为 `sandbox` 时是测试环境，不会真的叫车：回复开头说「测试模式」。

## 流程：先询价，用户确认后才下单

1. **询价**（不花钱）：用户说「帮我叫车去公司」「打车」，或者对你上一句「要帮你叫车吗」回答「要」「好」——跑 `estimate`，回复：「去公司的`product`大约 `price` 元，确认叫车吗？」`price_discounted` 有值时加一句「用券后 X 元」。
2. **下单**（花钱）：**只有**你上一句刚报过价、用户这一句明确确认（「确认」「确认叫车」「叫吧」）时，才跑 `order`。用户说别的、含糊的、或者没报过价，都不要下单。
   - 成功：说车型、车牌（`driver.car`、`driver.plate`）、多久到（`driver.eta_min`）；`pushed_to_phone` 为 true 就加一句「车牌发到你手机了」。还没匹配到司机就说「已经下单，正在找司机」。
   - 失败：照 `error` 说原因（比如询价过期了就重新报价、到每天上限了、已有一单在进行）。
3. **车到哪了**：跑 `status`，说司机状态、车牌、还有多远多久。`active` 为 false 就说没有进行中的订单。
4. **取消叫车**：跑 `cancel`，说结果。

回复按 AGENTS.md 的原则，一两句说清楚；车牌按字逐个念（「京 A 一二三四五」）。
