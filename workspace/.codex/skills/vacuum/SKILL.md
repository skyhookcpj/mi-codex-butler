# vacuum

所有操作只通过这个脚本（工作区相对路径），用装好的专用 Python 跑；不要用 mihome、小爱指令或其他方式控扫地机：

```
~/.mihome/dreame-venv/bin/python .codex/skills/vacuum/vacuum.py <命令>
```

| 用户说 | 命令 |
| --- | --- |
| 扫地机在干嘛、扫完了吗、还剩多少电 | `status` |
| 开始扫地、全屋扫一下、继续扫 | `start` |
| 扫一下客厅、把主卧和书房扫了 | `clean 客厅`、`clean 主卧 书房`（可以一次多个房间） |
| 暂停、等一下 | `pause` |
| 别扫了、停下 | `stop` |
| 回去充电、回去吧 | `dock` |
| 让扫地机去客厅、到主卧去（只过去，不扫） | `goto 客厅`（一次一个房间） |
| 有哪些房间 | `rooms` |
| 现在是什么模式 | `mode` |

脚本输出一行 JSON，`ok` 为 false 时照 `error` 或 `reason` 回话。

## 清洁模式

`start` 和 `clean` 都可以加 `--mode <模式>`，模式只有四种：`扫地`、`拖地`、`扫拖`、`先扫后拖`。

**用户没说模式就是扫地，不加 `--mode`。** 只有用户明确说了才加：

| 用户说 | 模式 |
| --- | --- |
| 扫一下、扫地、吸一下 | 不加（扫地） |
| 拖一下、拖地 | `--mode 拖地` |
| 扫拖、边扫边拖、扫完顺便拖 | `--mode 扫拖` |
| 先扫后拖、扫完再拖 | `--mode 先扫后拖` |

例：「把客厅拖一下」→ `clean 客厅 --mode 拖地`；「全屋扫拖一遍」→ `start --mode 扫拖`。脚本每次开扫前都按这次的模式设一遍，不沿用上次。

## 房间名

`clean`、`goto` 的房间名必须是 `rooms` 里有的名字。用户的说法对不上时（「大卧室」「孩子房间」），先跑 `rooms` 看有哪些，挑意思明确对得上的；拿不准就问用户，不要猜。脚本返回 `reason: unknown_room` 时，把 `rooms` 里的名字念给用户选。

用户说在 App 里改过地图或房间名，跑一次 `rooms --refresh`（约 5 秒）。

## 晚上开扫、出发要确认

`start` / `clean` / `goto` 返回 `need_confirm: true`（22:00–8:00）时，不要再跑别的，回一句：「现在是晚上，确定要开始扫吗？」（`goto` 就问「现在是晚上，确定让它去客厅吗？」）

**只有**你上一句刚问过、用户这一句明确确认（「确定」「扫吧」「对」）时，才带上 `--confirm` 重跑同一条命令（原来的房间和 `--mode` 都保留）。用户说别的、含糊的，都不要加 `--confirm`。

## 怎么回话

- `status`：先说状态（`state`），再说电量（`battery`）。正在扫时加上扫了多久（`cleaning_minutes` 分钟）、多大面积（`cleaned_area_m2` 平方米）。有 `error` 就说出来。
- 开始 / 按房间扫成功：按 `mode` 说，比如「客厅开始扫了」「客厅开始拖地了」「全屋开始扫拖了」。
- `status` 里有 `mode`，用户问模式时照着说。
- `reason: already_cleaning`：「已经在扫了」，顺带说一下当前状态。
- `reason: error`：说出 `error`，比如「扫地机卡住了：轮子悬空，得去看一下」。
- 暂停、停止、回充成功：一句话说清，比如「暂停了」「回去充电了」。
- `goto` 成功：「扫地机往客厅去了」。到了以后它会停在那里，要它回来就说回去充电。`reason: low_battery`：「电量只有 N%，先充会儿电」。

按 AGENTS.md 的原则，一两句话说清楚，不念 JSON、did、编号。
