# go-to-work

用户说「我要上班去了」「去上班了」「上班去了」这类出门上班的话时用这条 skill。不一定是早上，不要按早上来问候。

## 做法

1. 只跑一条命令（工作区里的相对路径）：

   ```
   python3 .codex/skills/go-to-work/briefing.py
   ```

   它会同时执行配置好的设备动作、查天气、查今天的飞书日程，输出一段 JSON。配置在 `~/.mihome/go-to-work.json`（样例 `go-to-work.example.json`），没配置的项 JSON 里就没有。别再单独调 mihome、lark-cli 或联网搜索，**除了脚本动的设备，别的设备都不要动**。

2. 按 JSON 组织**一段播报**。这条 skill 的回复可以比平时长：250 字以内，口语化，时间说成「上午十点半」「下午两点」。顺序：
   - 开场一句就行，比如「好，上班前帮你看了下」；
   - 设备：有 `devices` 就按 `devices.what`（脚本做了什么）一句话带过，比如 what 是「拉开客厅窗帘」就说「客厅窗帘给你拉开了」；
   - 天气：`weather.city` 现在的天气和温度；`next_6h` 里接下来会不会下雨（`rain_from` 是最早可能下雨的钟点）、温度区间；`umbrella` 为 true 或接下来要下雨就提醒带伞；
   - 日程：有 `agenda` 才说，点明来源，比如「你的飞书日程里」。只说还没结束的（`ended` 为 false）：
     - **接下来最近的 1 到 2 个展开说**：几点开始、开多久（`minutes`）、标题、用一句话概括 `about` 讲什么、是不是飞书视频会议（`online`）或在哪（`location`）、还没回复的提一句；
     - 其余的一句带过（「之后还有两个会」）；全天日程（`all_day`，比如假期）单独提一句；
     - `pending_rsvp` 大于 0 就提醒「有 N 个邀请还没回复」；`upcoming` 为 0 就说今天没有别的安排了。

3. 顶层 `ok` 为 false 是配置读不了，照 `error` 说一句就行。某一项 `ok` 为 false：简单带一句原因（比如「日程没查到，飞书授权可能过期了」），其他照常播。

4. 播报的最后问一句：「要帮你叫车去公司吗？」不要报价格。用户回答「要」时按 taxi skill 先询价、再等确认。

## 之后的追问

用户接着问日程或天气（「第二个会在哪」「晚上会下雨吗」），先用这次 JSON 里的信息回答；不够再跑 `lark-cli calendar +agenda --as user --format json` 查详情（可加 `--start` / `--end` 查别的日期）。
